WarpDrive

Object storage built for disaggregated systems

Warpdrive is a purpose-built S3-compatible object store focused on workloads that demand high throughput — storage-disaggregated databases, ML training pipelines, and agentic workflows that move computation close to data.

Get started View characterization study

An S3ish rocket store

Modern databases, agents, and training systems are building on top of object stores. But historically, high-efficiency systems have never benefited from an opaque storage layer. Object stores were designed for archival and customer file uploads, and that opacity was fine for those use cases. Now latency-sensitive systems are building on the same interface. Through our characterization work we have identified a few early parameters that capture how disaggregated workloads actually use storage, and we expose these so developers can tune them analytically from their own workload behavior. We think both sides benefit when the storage layer is legible and you can reason about its internals, develop against its behavior, and work together toward a system that is genuinely cost-efficient.

Disaggregated databases

Modern databases like Neon, SlateDB, and TidesDB separate their storage layer from compute. They ship their WAL segments, SSTables, and layer files to object storage — and expect it to keep up.

Agentic workloads

Agents manage state, memory, and tool outputs at runtime. They need fast, consistent object storage with predictable latency — not the eventual consistency and cold-start penalties of cloud S3.

Training & checkpointing

ML training jobs checkpoint model state to object storage continuously. Warpdrive provides the throughput and S3 compatibility to serve as a local or rack-local checkpoint store without changing a line of training code.

What Warpdrive provides

A storage layer designed for the systems that need it most.

S3-compatible API

Drop-in replacement for AWS S3. Any client or library that speaks S3 works without modification — boto3, aws-sdk-rust, the official CLIs.

High throughput

Built for workloads where throughput and low latency matter: serverless databases, ML checkpointing, and distributed system state storage.

Compute-storage separation

First-class support for storage-disaggregated architectures. Run storage and compute independently, scale them separately, attach either to S3 clients.

S3 operation characterization

A characterization study of S3 API usage in storage-disaggregated Postgres. Using sysbench TPC-C (scale=10) against Neon backed by Warpdrive, we measure how S3 op counts scale with tenant count under warm-cache and cold-start conditions.

Finding: In steady state with a warm pageserver cache, S3 GET operations approach zero — Neon's page cache absorbs all reads. GETs occur only during cold starts when the pageserver rehydrates layer files from Warpdrive. The GET count scales super-linearly with tenant count (4T → 11 GETs, 8T → 48 GETs), consistent with increased page cache pressure, but absolute cost remains negligible: $0.0000392 for an 8-tenant cold start.
